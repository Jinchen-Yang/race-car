### 与代码注释/旧文档冲突时以下面为准的事实

1. **r20 起编码器仅遥测**（`DRIVE_OPEN_LOOP=1`，app.c:132）：速度闭环已弃用，行驶=开环占空+DeltaYaw PD。一切"速度环"通道（ch4/ch6/ch8/ch9）语义按开环理解。
2. **右轮每圈计数现役真值 = 254.35**（encoder.h:46，2026-07-05 推车定案）；**265.2 是被接触抖动污染 +4% 的废值**，app.c:57 注释仍是旧的（本 PR 已修 功能状态清单.md）。
3. 供电拓扑：电机/驱动板=电池 ~12V（须为 3S 锂电，TB6612 上限 13.5V）；主控+灰度=USB/充电宝；舵机轨=驱动板 5V（巡线模式全程断电）。
4. 定版参数（README §3）**不要轻动**：SEG_LINE_TH 从 8 调松到 63 曾引发假事件链式推进事故（ecd21e9）。
5. 串口在线调的参数**断电即失**，定版值必须写回 app.c 再烧。`MOTOR_MAX_DUTY=600` 是 7.4V 电机对 12V 电池的防超压约束，禁止提高。

## 1. 第一优先：判别实验（按序执行，零改码）

VOFA+ 连 XDS110 口 115200 JustFloat；通道定义=empty.c:239-264。无线/离线采集见 §3。

### 实验 A：区分"IMU 谎报" vs "执行端不足"（跑一趟坏的即可）

操作：正常复现一次"跑不直"，全程录 VOFA。
看：**ch4(DeltaYaw) + ch21(差速)**，对照目视轨迹。（通道语义=r31 RUN 态重用，app.c:548-556；empty.c 的通道注释是旧的，以 README §4 / tools/parse_justfloat.py 的 CH_NAMES 为准。）
- 车在画弧、而 ch4≈0 且 ch21≈0 → **控制器自认走得很直 = yaw 参考漂了 → IMU 实锤，跳 §2-修复①**。
- ch4 单调增大、ch21 恒偏一侧顶着 → 执行端不足（配平/电压）→ 做实验 D。

辅证（每趟顺手做）：趟末把车摆回出发朝向，读 ch12 与该趟 START 时刻值之差 = 整趟净漂移；**趟间递增 = 温漂实锤**。

### 实验 B：灰度供电/总线（与 A 同一趟数据就能看）

看：**ch14（灰度 I2C fail 累计）斜率** + ch15（原始字节）。
- 坏趟 ch14 台阶/斜坡上涨、同期 ch13 停涨、ch15 长时间冻结 → **供电/总线实锤，跳 §2-修复②**。
- 对照实验：同占空，充电宝 vs 电脑 USB 各跑一趟，比 ch14 斜率。烧录后首跑顺畅的一个候选解释就是"那趟还挂着电脑 USB"。

### 实验 C：复位链核验（10 秒，顺手闭案）

第二次 START 后立即看：ch6(段号)=0、DeltaYaw≈0、ch20=当拍 ch12。三者吻合 → "跨 RUN 状态残留"假设闭案（分析已核对复位清单完备，此实验只是保险）。

### 实验 D：电池闭案实验（仅当 A 指向执行端时做）

满电 vs 亏电各一趟，同占空下比 ch1/ch2 计数斜率折算实际速度。降幅 <20% 而直线照崩 → 电池主因否决，回头查配平/机械。

### 模式 4 专属（lap2 起步偏才做）

ch20 每次过 A 的台阶高度：接近 ±10° 且方向与跑偏一致 → 重锚噪声注入实锤（r29 是限幅不是消除）；修法=重锚改用出线后直线段稳定 0.5s 的 yaw 均值。

## 2. 判别后的修复菜单（细节全在审计 §4，此处只列指挥顺序）

**无论判别结果如何都建议做的三个小修**（互相独立，各自可单独烧录验证）：
1. 灰度失败帧显式当"无数据"：gray_get_diag 加 fresh 标志，失败帧不推进 g_nodata/不喂 ladder（堵 gray.c:93 冻结字节 × app.c:485 无条件消费的真实缺陷）。
2. START 前重校准 IMU 零偏（IDLE 静置 ≥2s 检测）+ 校准失败禁止 START（现在 3 轮失败仅亮灯仍放行）。
3. g_dyaw_prev 在段切换/AIM 返回时清零（一行，消 derivative kick）。

判别指向 IMU（①）→ 追加：温漂补偿 bias(T)（temp 数据已在 out->temp 里，白送）。
判别指向供电（②）→ 追加：实测灰度 I2C 总线高电平（手册要求 ≥3.6V，主控是 3.3V 总线，两头都不干净，审计 §2.4）；换供电路径复测。
每次烧录后：**查 boot 横幅 rN 版本号**，每轮改动一条 commit（现象→机理→修复），沿用 git log 的记录纪律。

## 3. 数据采集与离线分析（现场没有 VOFA 经验的队员用这条路）

- 台架：`python3 tools/log_serial.py <XDS110串口>` 录原始流。
- 真场地：ESP32 蓝牙桥（[tools/esp32_bt_bridge/](tools/esp32_bt_bridge/esp32_bt_bridge.ino)，接线/供电红线见文件头注释——**桥的电源严禁挂主控那个充电宝，会污染实验 B**）；或 OpenLog 类串口 SD 模块并联 UART0 TX 当黑匣子。
- 解析：`python3 tools/parse_justfloat.py capture_*.bin` → CSV + 健康速览（I2C 成败增量、yaw 净变化）。**你自己直接分析 CSV**：实验 A/B/C 的判据都能在数据上自动跑，不用队员盯波形。
- 建议先做的一行固件改动：task_vofa 加 `(float)g_tick_ms` 当 ch24（`vofa_send(ch,25)`，解析器加 `--channels 25`）——离线才有真实时间轴，还白送调度抖动量化（验证审计 §3.1 的 task_vofa 阻塞结论）。

## 4. 安全红线（对队员的每条指令前自查）

- 摆车离胶带 ≥50cm 再 START（起步保护 1.5s 无视灰度）。
- 运动中任意键=急停；ESTOP 下 2s 内三连按 START 软清障。
- 别动：SEG_LINE_TH/BLANK_TH、MOTOR_MAX_DUTY、每圈重锚 ±10°。
- 5V buck 割接时灰度与舵机**严禁共轨**（感为手册强制条款，尖峰烧传感器）。
- 舵机端点当前先收窄到 0.6–2.4ms，角度也有限位；AIM 相关调试仍必须先按 [servo_gimbal_bringup.md](servo_gimbal_bringup.md) 扫两端实测回填，否则可能顶机械限位堵转。
