# 代码复现规范

“在自己电脑上能跑”不算复现。通过标准是另一名队员在空目录、按文档完成构建、烧录、接线、自检和一组基准测量。

## 每道题的最小目录

用 `tools/new_problem.sh 20260724-measurement-a` 创建：

```text
problems/<代号>/
├── README.md
├── requirements.md
├── verification.md
├── bom.csv
├── firmware/
├── hardware/
├── evidence/
└── release/
```

## 必须固定的信息

- Git 提交号、题面版本和选题时间。
- CCS Theia、MSPM0 SDK、SysConfig、tiarmclang 的准确版本。
- 核心板版本、原理图来源、`pinmap.yaml`、时钟、供电和跳线。
- 一条从导入工程到烧录的完整路径；烧录后可见固件水印。
- 校准数据、原始测试数据、测试仪器和环境条件。
- release 中的 `.out/.hex`、设计报告、BOM、校准文件及 SHA-256。

## 当前工具链基线

旧项目已验证：CCS Theia + MSPM0 SDK `2.10.00.04` + SysConfig `1.26.2` + tiarmclang。新通用模板在 07-18 完成前沿用这一组合，禁止临赛当天升级。

旧工程没有可靠的本地 Make/CMake 构建入口；在建立并验证命令行导出流程前，CCS 导入/构建步骤必须截图或逐项记录，不得声称“一键复现”。
